# 定位依据

以下 VA 基于分析数据库 imagebase `0x140000000`。运行时仅按特征码寻找函数，不将这里的地址硬编码为定位结果。

## 素材倍率

`sub_14005B900`（RVA `0x5B900`）是一个 16 字节叶函数：

```asm
xor eax,eax
cmp edx,4
cmova edx,eax
mov eax,[rcx+rdx*4+4A68h]
ret
```

原行为：种类 0～4 读取探索状态对象的百分比倍率数组，超出范围回退到 0。通过结算函数 `sub_1401A29F0` 的调用链确定：1～4 用于四类素材，0 对应货币。该结算函数先读取倍率、除以 100、乘基础数量，再交给库存增加函数。`sub_1402C1AB0`、`sub_1402BB3D0`、`sub_1402C3120` 的奖励界面也调用它。

补丁用 14 字节 RIP 间接绝对跳转加 2 字节 NOP 替换整段叶函数。1.1 版对 0～4 均返回配置百分比，包含币及四类素材；仅对越界类型保留原对象的货币倍率回退。1.0 版曾将 0 排除，导致用户截图中第一行币仍为 150%，而其余四行均为 500%。对象偏移从匹配到的原指令中解码，不依赖固定对象指针。不使用 trampoline。

## 礼物喜好

沿 `tex_f_present_favorite_icon` 字符串追踪到 `sub_14028DFB0`，它使用列表记录偏移 `+0x10` 选择图标。

列表构建函数 `sub_14028BA10` 读取 `FieldPresentReactionType` / `FieldPresentReaction`，随后调用 `sub_14005CC30` 检查赠送历史。未满足历史条件时写入 5（未知图标），否则将礼物类型表中对应角色的喜好写入 `+0x10`。

在 RVA `0x28BBEC` 将 `75 0A`（条件跳转）改成 `EB 0A`（无条件跳转）。只绕过该列表的未知显示分支，历史查询本身、真实反应、好感度及历史写入逻辑不变。特征码包括前面的参数准备、历史查询、未知图标写入及真实喜好读取，长度 46 字节，调用位移使用通配符。

## 加载

游戏导入 `WINMM.timeBeginPeriod` / `timeEndPeriod`。代理导出首次被调用时，`InitOnceExecuteOnce` 载入 System32 中真实 WinMM，校验配置，扫描全部启用的补丁点后写入。`DllMain` 仅保存自身模块句柄，不进行文件读取、扫描或加载依赖。

只对文件名为 `HUNDRED_LINE.exe` 的主程序打补丁。源码中的初始化不提供运行中注入入口。补丁函数所在 DLL 固定保留到进程退出，避免代理被卸载后留下悬空跳转。动态代码写入使用 `VirtualProtect`，恢复保护并刷新指令缓存。

验证器从游戏文件复制真实机器码进行执行验证；礼物片段通过汇编适配器设置原分支需要的 R14、RBP 和 AL。无需启动游戏，不改变原文件。
